# AVT 补货计划填充 · Windows

统一处理 US、CA、EU、UK、JP 的 Rust 应用。Windows 界面使用系统原生控件，不依赖 Python、浏览器或 OpenGL。

## 使用

1. 将便携包完整解压，双击其中的应用即可，无需安装 Python 或 Rust。
2. 双击 `AVT-Replenishment.exe`，将目标补货计划 `.xlsx` 拖入窗口。也可选择文件或粘贴路径后点击“识别”。
3. 核对站点、日期、源文件、行数和转换数量；若出现缺失文件或多个候选文件提示，核对后勾选确认项。
4. 按需勾选“填充前备份原表”。默认勾选；取消则不产生备份。
5. 点击“确认填充并覆盖原表”。填充完成后在 Excel / WPS 中打开原表，由表格软件重算公式。

目标平台为 Windows 10 / 11，64 位 x86。处理时关闭目标文件的 Excel / WPS 窗口。每次处理一份补货表。

## 目录规则

程序以拖入的补货表所在目录为起点，不需要固定盘符，也不依赖程序放在哪里。

```text
补货计划/
  AVT-UK/
    AVT-UK-20260824全站点通用补货计划.xlsx
    FBA库存/
      库存文件.txt
    限制发货数量/
      限制发货文件.csv
    业务报告/
      20260824/
        AVT-UK-7T-20260824.csv
        AVT-UK-14T-20260824.csv
        AVT-UK-30T-20260824.csv
        AVT-UK-60T-20260824.csv
        AVT-UK-90T-20260824.csv
```

- US / CA / UK / JP 按各自站点匹配报告；CA 文件名中的额外横线和空格可以保留。
- EU 目录内的补货表可以使用 `AVT-FR-日期…`、`AVT-DE-日期…` 或 `AVT-EU-日期…`。EU 业务报告位于日期目录下各国子目录，例如 `业务报告/20260824/DE/AVT-DE-7T-20260824.csv`。
- US 的 MX 报告位于 `业务报告/日期/MX/`。
- FBA库存和限制发货数量选择各自目录里修改时间最新的受支持文件；业务报告按站点、周期和目标日期精确匹配，同名不同格式时选择修改时间最新的文件。
- 忽略 `~$` 临时文件、点文件、名称含 backup 或“备份”的文件。
- 源数据支持 CSV、TXT、TSV、XLS、XLSX；Excel 源文件读取第一张工作表。目标补货表仅支持 XLSX。

## 保留的业务逻辑

只更新 `FBA库存`、`限制发货数量`、`7天销`、`14天销`、`30天销`、`60天销`、`90天销`。
每次清空对应表中的旧值再写入新值，保留原有样式、列宽等表格结构；没有源文件的表保留旧数据，并在确认前提示。

- US：先写 US，再空两行追加 MX，不重复 MX 表头。某周期仅有 MX 时，沿用旧脚本规则，以 MX 表头和数据替换该周期。
- EU：按 DE、FR、IT、ES、IE、NL、BE、AT、PL、CZ、HU、RO、BG、HR、SI、SK、LT、LV、EE、LU、MT、CY、SE、TR 顺序，拼接实际找到的报告。国家之间空两行，每国有表头，并在该国表头 Q 列写国家代码。
- 普通站点：直接替换对应周期的数据，保持源报告列顺序。

## 普通数字转换：固定列位置，不识别表头

| 站点 | 业务报告列数 | 转换列 |
|---|---:|---|
| US / CA / JP（US 内的 MX 也沿用此布局） | 21 | D、E、H、I、N、O、T、U |
| UK / EU | 15 | D、F、I、J、N、O |

这些是样表中的数量指标列。识别到其他列数时停止填充，不猜测、不重排列。

- 数量文本 `123`、`1,185`、`1.185`、`1 185` 可转换为真正数值；分组分隔符须一致。
- 货币、百分比列的内容保持源数据原样，不去货币符号、不除以 100，也不统一显示格式。
- ASIN、SKU、标题等标识和文本列保持原样，包括前导零。
- 不执行源文本中以 `=` 开头的内容；按文本写入。
- 不支持的数量文本保留原值；超过 15 位数字的文本不会强制转换，避免精度丢失。

## 保存

确认填充前不写原表。填充时核对原表和源文件是否在识别后发生变化，先写同目录临时文件并验证，再替换原表。
未修改的 XLSX 部件会逐项进行字节比对；其他工作表、公式和外部链接保持原内容。
工作簿会标记为下次打开时重算，不在 Rust 应用内模拟 Excel 公式计算。

勾选备份时，生成 `原文件名_backup_日期时间.xlsx`，备份失败则不覆盖原表。填充结果仅在界面显示，不在本地生成或保留 JSON 操作记录。
取消备份时不创建备份文件，仍执行临时文件写入与校验。

样表中已有的 `#VALUE!`、`#REF!` 等公式问题不由填充应用自动修改。

## 验证范围

详见同包 `验证说明.md`。实际下载的原始业务报告尚未提供，编码和分隔符测试使用构造文件；五份真实补货模板通过副本测试，原件未修改。

## 从源码编译

安装 Rust 稳定版及 Windows C++ 构建工具，进入源码目录运行：

```powershell
cargo test --locked
cargo build --release --locked --bin AVT-Replenishment
```

生成文件为 `target/release/AVT-Replenishment.exe`。正式发布包由 GitHub Actions 的 Windows MSVC 环境构建，静态链接 C/C++ 运行库。

也提供 `avt-cli` 源码用于自动化测试。`inspect` 只读；`apply` 会修改指定文件：

```powershell
cargo run --bin avt-cli -- inspect "C:\补货计划\AVT-UK\AVT-UK-20260824全站点通用补货计划.xlsx"
```

核心文件：`src/core.rs`（站点、匹配、解析和数字规则）、`src/xlsx.rs`（局部替换与校验）、`src/windows_ui.rs`（原生界面）。

## v1.2.0 应用内更新与置顶

- “图钉置顶”勾选后窗口保持最上层，再点一次取消；只对当前会话有效。
- “检查更新”查询私有仓库 Perfect9s/AVT-Replenishment 的最新正式版本。发现新版后点击“下载并更新”，应用自动下载、核对 GitHub 提供的 SHA-256 和文件大小，退出旧程序、替换应用并重启，无需手动下载解压。
- 首次检查时在系统授权框的密码栏填写 GitHub Token（不是登录密码）。建议创建 fine-grained Token，仅选本仓库，授予 Contents: Read-only 权限。
- 授权框不勾选保存则仅本次会话有效；勾选后由 Windows 凭据管理器保存。可用“更新授权”更换、“清除授权”删除。不生成本地 JSON 设置或操作记录。
- 补货处理无需联网或 GitHub 授权。只有点击检查更新或下载更新时才访问 GitHub。

更新需要应用所在文件夹可写，并关闭同一应用的其他实例。下载失败不会退出或修改旧程序；更新助手会等待旧进程退出，替换或创建新版进程失败时尝试恢复旧程序。更新不改动补货表。成功重启后自动清理临时更新文件夹；异常中断时可能留下 `.avt-update-…` 文件夹，其中 `old.exe` 为旧程序。只更新应用 EXE，包内说明文件不会自动替换。
